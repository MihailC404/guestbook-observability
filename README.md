# guestbook — стартовый репозиторий для Модуля 2 (наблюдаемость)

Гостевая книга на FastAPI + PostgreSQL. Проект уже прошёл весь путь Курса 1 «Дорога в прод»: контейнеризирован, настроен, секреты вынесены в `.env`. Можно поднять одной командой:

```bash
docker compose up --build
```

## Что умеет

- `GET /` — приветствие
- `GET /health` — проверка «жив ли сервис»
- `GET /messages` — список сообщений
- `POST /messages` — добавить сообщение: `{"author": "...", "text": "..."}`

## Текущее состояние: сервис слепой

Сервис работает, но ничего не рассказывает о себе:

- `/health` — заглушка, всегда отвечает `ok`, не различает «жив» и «готов обслуживать»;
- логи — обычный текст uvicorn, не структурированы;
- метрик нет вовсе — нельзя ответить на вопрос «сколько запросов в секунду» или «какая доля падает»;
- нет дашборда, нет алертов — если сервис упадёт ночью, никто не узнает, пока не пожалуется пользователь.

## Твоя задача

Дать сервису полноценную наблюдаемость: разделить healthcheck на liveness и readiness, перейти на структурированные логи, инструментировать RED-метриками, поднять Prometheus и Grafana с дашбордом, настроить алерты через Alertmanager с собственным вебхук-приёмником и проверить всё это управляемой нагрузкой через k6.

Полное задание — в методичке воркшопа. **Бизнес-логику (эндпоинты `/messages`) менять не нужно** — фокус на наблюдаемости и эксплуатации.
