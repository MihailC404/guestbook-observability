# guestbook — стартовый репозиторий

Гостевая книга на FastAPI + PostgreSQL. Проект уже прошёл весь путь: контейнеризирован, настроен, секреты вынесены в `.env`. Можно поднять одной командой:

```bash
docker compose up --build
```

## Что умеет

- `GET /` — приветствие
- `GET /health` — проверка «жив ли сервис»
- `GET /messages` — список сообщений
- `POST /messages` — добавить сообщение: `{"author": "...", "text": "..."}`

## Подготовка репозитория

1. Форкните репозиторий воркшопа к себе.
2. Склонируйте и заведите рабочую ветку:

```bash
git clone https://github.com/ВАШ-ЛОГИН/guestbook-observability.git
cd guestbook-observability
git switch -c observability
```

3. Убедитесь, что стартовое состояние работает: `docker compose up --build`, затем `curl http://localhost:8000/messages`.

## Текущее состояние: сервис слепой

Сервис работает, но ничего не рассказывает о себе:

- `/health` — заглушка, всегда отвечает `ok`, не различает «жив» и «готов обслуживать»;
- логи — обычный текст uvicorn, не структурированы;
- метрик нет вовсе — нельзя ответить на вопрос «сколько запросов в секунду» или «какая доля падает»;
- нет дашборда, нет алертов — если сервис упадёт ночью, никто не узнает, пока не пожалуется пользователь.

## Ваша задача

Нужно получить тот же проект, но наблюдаемый:

- **liveness и readiness** разведены: `/health` дёшев, `/ready` честно проверяет базу и отдаёт 503;
- **структурированные логи** (JSON) на каждый запрос, без секретов;
- **RED-метрики** (счётчик запросов + гистограмма задержки), отданные на `/metrics`;
- **Prometheus и Grafana** в Compose, автонастроенный источник данных, собранный дашборд RED;
- **Alertmanager** с хотя бы одним рабочим правилом и собственным вебхук-приёмником в самом сервисе;
- **k6-сценарий**, который управляемой нагрузкой вызывает алерт, — и вы видите это своими глазами: в Prometheus, в логе сервиса.

### Приёмочный тест — доказательство, что всё работает

1. `docker compose up --build` — все пять сервисов подняты (`app`, `db`, `prometheus`, `grafana`, `alertmanager`).
2. `curl -i http://localhost:8000/health` и `.../ready` — оба 200 при живой базе.
3. `docker compose stop db` → `/health` всё ещё 200, `/ready` — 503. Верните базу.
4. `curl -s http://localhost:8000/metrics | grep http_requests_total` — есть строки с реальными счётчиками.
5. `http://localhost:9090` → **Status → Targets** — `seed-service`/`guestbook` в состоянии `UP`.
6. В Grafana открыт дашборд RED с тремя панелями, источник данных настроен автоматически.
7. `k6 run load-test.js` создаёт нагрузку, которая **реально** переводит правило в `firing` — видно в `http://localhost:9090` → **Alerts**, и в `docker compose logs app | grep alert_received` есть запись от вашего вебхук-приёмника.
